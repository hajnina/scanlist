### Failures hit on the way (all fixed, kept for the record)

1. `pluginManagement {} must appear before any other statements` — the npm bootstrap in
   `android/settings.gradle` had to move *inside* `pluginManagement {}`.
2. `scripts/android-env.sh` exports the **newest** build-tools aapt2; after installing build-tools
   37.0.0 for RN 0.88 that is an x86_64 ELF again. `build.sh` now re-selects an aarch64 aapt2 and
   strips the stale `-D` from `GRADLE_OPTS`. **Lead action (outside owns):** general fix belongs in
   `scripts/android-env.sh` — prefer an aarch64-ELF aapt2 over "newest".
3. RN's default NDK 27.1 is x86_64-only, but the new architecture *does* compile C++ in the app
   module (`ReactAndroid/cmake-utils/default-app-setup/CMakeLists.txt`). NDK 30.0.16248370 in the
   shared toolchain has `linux-aarch64` prebuilts → `-Pscanlist.ndkVersion` (property, not a path).
   This is why the native build works locally at all.
4. Jest: `react-native-safe-area-context` renders children only after onLayout → its shipped jest
   mock (`jest.setup.js`); spring timers needed fake timers + unmount to avoid a teardown crash.
5. No keystore in git ⇒ the debug signing config would fail on CI. Fixed with an on-demand
   throwaway keystore (`scripts/make-debug-keystore.sh`) called from `android/app/build.gradle`.
6. The lead-owned CI `rn` job runs `./gradlew assembleDebug` with no npm step, but RN autolinking +
   the included `:react-native` Gradle plugin live in `node_modules` (gitignored). `settings.gradle`
   now runs `npm install` once when `node_modules/react-native` is missing (kept inside `owns`).

so RN 0.88 + new arch (4 ABIs of CMake/native glue) builds on the x86_64 runner with RN's default

the next, lead-owned step:

```
##[error]mv: cannot stat 'apps/rn/android/**/outputs/apk/debug/*.apk': No such file or directory
```

**Workflow reason, not this card's code.** `.github/workflows/pr.yml` (`rn` job, "Rename APK") uses
`mv apps/rn/android/**/outputs/apk/debug/*.apk …`, but the Actions shell runs bash without
`globstar`, so `**` behaves like `*` and the real path has two segments
(`app/build/outputs/apk/debug/`). The step's `if: hashFiles('apps/rn/android/**/outputs/…')` still
matches (the expression language does support `**`), which is why the step runs and then fails.
One-line fix (lead, `.github/` is outside `owns`) — mirror the kotlin job:

```yaml
run: mv apps/rn/android/app/build/outputs/apk/debug/*.apk ScanList-rn-debug.apk
```

(the `if: hashFiles(...)` and `upload-artifact` paths are fine as they are, or use
`apps/rn/android/app/build/outputs/apk/debug/*.apk` in both). No change on my side can fix it
without either editing `.github/` or copying the APK to a fake `*/outputs/` directory, which I did
not do.
