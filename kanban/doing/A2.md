  rebuildable cache of `{id, updatedAt}` (order on the home screen); a missing/corrupt index is
  rebuilt from the keys and a corrupt document is skipped, never partially loaded (LIST.md §5).
  Imports never deduplicate (LIST.md §6), each gets a fresh slug id.

- **`ui/`** — `ListsScreen` (hero progress, file/paste import with pointered errors, stored list

### Decisions / limits, for review

1. **AsyncStorage 3.x → 2.2.0.** 3.x applies KSP + Room (legacy-storage migration) in the Android
   build; 2.2.0 is the plain-library line (KSP only behind `useNextStorage`) and is the lower-risk
   native surface for the x86_64 CI build. Both support the new architecture; the JS contract here is
   just `getItem/setItem/removeItem/getAllKeys`.
2. **"Save to a file" is not offered.** The document picker's `saveDocuments()` needs a source URI on
   disk (`sourceUris`), which would need a filesystem module; the card's export trio is "share/save/
   copy via RN Share/clipboard", so SHARE (system sheet with the JSON text + file-name title) and COPY
   are implemented. SAVE is a 10-line follow-up once a temp-file module is sanctioned.
3. **File import reads the picked URI with `fetch(uri).text()`** (RN fetch + Blob handle `content://` /
   `file://`; this is the documented pattern of the predecessor `react-native-document-picker`).
   **Not verified on a device** — no phone is on adb (same blocker class as B0). If it misbehaves on
   Android 14+, the fallback is the picker's `keepLocalCopy` + a filesystem module; paste import
   exercises the identical parse path and definitely works.
4. **`TextEncoder` declaration (`src/list/dom-globals.d.ts`).** ts-core's SHA-1 hashes UTF-8 via
   `TextEncoder`; RN's TypeScript lib has no `dom` lib, but the Hermes runtime RN 0.88 ships provides
   the API. The declaration is one class, documented — deliberately not the whole DOM lib.
5. **Delete/list management is repository-only** (`remove()` is implemented + tested) but the home
   cards do not expose a delete button yet: B2 has one, and deleting a list is destructive. Say the
   word and it is 5 lines.
6. **A4/A5 will want the ranking layer on top**: `buildListTree` returns `ItemNode.flat` (ts-core
   `FlattenedItem`), i.e. the exact `RankItem` minus `vec`, so A4 can pass these straight to
   `rank()` without another flatten.
