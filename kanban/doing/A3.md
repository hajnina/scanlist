### What was built

1. **Native module** `apps/rn/android/.../rn/embed/`:
   * `EmbedModule.kt` — a plain `ReactContextBaseJavaModule` named `Embed` over
     `shared/android-embed`: `embedDocs(texts[])`, `embedQuery(text)`, `embedImage(base64|uri)`,
     `status()`, `close()`, plus constants (`name`, `modelId`, `dims`, `backend`, `modelPresent`,
     `supportsImages`, `linked`). All calls serialise on one worker thread (the ladder is not
     thread-safe, JS never blocks); the model is opened + self-tested on the first call and its cost
     is reported once as `openMs` (the call's own `latencyMs` excludes it).
   * Vectors cross the bridge as **base64 of little-endian float32** (`EmbedVectors.kt`), decoded in JS
     into a `Float32Array` — no JSON array of 256 numbers, per the card.
   * Errors are rejected with stable codes: `E_MODEL_MISSING`, `E_NO_BACKEND`, `E_UNAVAILABLE`,
     `E_INPUT`, `E_IMAGE`, `E_EMBED`. `E_MODEL_MISSING` carries the `scripts/model.sh push <package>`
     hint and is the expected state until B0/S6 provisions a phone.
   * `EmbedModel.kt` — finds the bundle in `<files>/models/<name>.litertlm` (internal, then external)
     and in `<files>/models/embeddinggemma-2-740m/<name>.litertlm` (`LiteRtEmbedder.defaultModelFile`).
   * `EmbedPackage.kt` — `BaseReactPackage`, `isTurboModule = false`.
2. **Registration**: `MainApplication.getPackages` adds `EmbedPackage()` (3 lines).
3. **JS** `apps/rn/modules/embed/`: `NativeEmbed.ts` (typed bridge lookup, TurboModuleRegistry then
   NativeModules), `index.ts` (detailed calls + the cross-track `Embedder` contract, `EmbedError`,
   `base64ToFloat32`), `README.md`, `__tests__/embed.test.ts` (11 tests).
4. **Dev screen** `apps/rn/src/dev/`: `DevEntry` adds **"Embed self-test (A3)"** to RN's own dev menu
   (shake / Ctrl+M / ⌘M, debug builds only) and opens `EmbedSelfTestScreen` in a modal — backend,
   dims, latency, model-open time, first six components of the first vector, engine facts, and the
   `E_MODEL_MISSING` hint card. `src/dev/__tests__/EmbedSelfTestScreen.test.tsx` renders both states
   (done + missing model) against a mocked native module.
5. **Gradle** `apps/rn/android/settings.gradle`: includes `shared/android-embed` by path, adds it to
   `:app`, raises `minSdk` to 31 and passes `-Xskip-metadata-version-check` to the app's Kotlin
   compiler. The A1 `npm install` bootstrap is untouched and still works.

### Why no codegen TurboModule (and why a legacy module is fine on new arch)

RN 0.88 resolves a legacy `BaseReactPackage` module through the legacy-module interop layer
(`ReactNativeNewArchitectureFeatureFlagsDefaults.useTurboModuleInterop() == true` for new arch +
bridgeless), so `TurboModuleRegistry.get('Embed')` sees it as a TurboModule. Codegen would need a
`codegenConfig` in a package-level `package.json` / an autolinked RN library — both outside `owns` —
and five methods gain nothing from a generated spec. README has the same note; A6/lead can migrate it.
