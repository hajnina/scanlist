- VisionCamera v5 (2026-04): barcode scanner split out to `react-native-vision-camera-barcode-scanner` (MLKit, MIT, both platforms); frame processors are Nitro Modules; ALWAYS `frame.dispose()`.

#### Architecture (why a photo every 400 ms)

I took the lead-note-sanctioned `Photo.getFileDataAsync()` route instead of frame processors:
`usePhotoOutput()` + `capturePhoto()` every 400 ms → `getFileDataAsync()` (JPEG bytes for image
embedding) **and** `saveToTemporaryFileAsync()` (the same JPEG on disk, which is exactly what ML Kit
v2's static-image APIs read: `processImageBarcodeScanning` / `processImageTextRecognition`). One
capture therefore feeds all three chips — barcode, OCR and image embedding see the same picture
(important for `score = max(image, text)` fusion) — and it avoids the Nitro-worklets Babel plugin,
`frame.dispose()` lifetime bugs, Skia, and the deprecated `frameProcessInterval` entirely. The
~2.5 fps self-gate is `createCaptureLoop` (default 400 ms, single-flight: a slow capture lowers the
rate, never queues).
