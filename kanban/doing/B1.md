### Work log 2026-11-16 (ag-b1)

**What landed** (all under `owns`; no other track/card touched):
- `apps/kotlin/app/` — single Compose app module, module id `:scanlistKotlin` via S9's repo-root
  `settings.gradle.kts` → `projectDir = apps/kotlin/app`. NO `apps/kotlin/settings.gradle.kts`,
  `apps/kotlin/gradlew` or `apps/kotlin/build.gradle.kts` was created (build contract). The module's
  `build.gradle.kts` applies the plugin ids WITHOUT versions (root pins AGP 8.7.3 / Kotlin 2.0.21).
- App id / namespace `dev.hajnina.scanlist.kotlin`; minSdk 30, compileSdk/targetSdk 35, Java 17.
- Deps pinned exactly like Bonsai (`STYLE_GUIDE.md` §1): activity-compose 1.9.3, runtime 1.9.0,
  ui/foundation/animation 1.8.2, **material3 1.4.0**. Deliberately **no Compose BOM** — the style
  guide records that the BOM pulls ui 1.9 → compileSdk 36; the B1 brief mentioned "material3 1.4.0 +
  compose-bom", but the reference it points at (`references/bonsai-ui/src/bonsai-serve/app/build.gradle.kts`)
  says no BOM, and that is the pair proven on this toolchain. Version comment is in the module file.
- M3 Expressive by hand (adapted from `references/bonsai-ui/src/bonsai-serve/app/src/main/java/dev/hajnina/llmserve/MainActivity.kt`,
  attribution comments in `Theme.kt`/`Components.kt`/`Screens.kt`): dynamic colour (API 31+) with
  teal/amber seed fallback, `enableEdgeToEdge()` + `WindowInsets.safeDrawing`, `Motion` object with the
  ExpressiveMotionTokens spring specs, `Heavy = FontWeight.Black` display type, 44dp hero + asymmetric
  16/52/16/52 leaf + 36/12/36/12 checkerboard tile shapes, 14dp round-capped progress bars, corner
  morph + colour crossfade on toggles, `springIn` stagger, `Pressable` press-scale (0.96 fastSpatial),
  haptics (Confirm / ToggleOn / ToggleOff) on every action.
- Screens stubbed: **Lists** (hero "N LEFT" + progress + 3 leaf list cards), **List** (back, hero count,
  14dp progress, section labels in JSON order, tick cards with line-through + shape/colour morph,
  all-ticked state), **Scan** (camera placeholder, barcode/text/image source chips, TOP MATCH hero with
  TICK ITEM button, ranked next-in-line cards), **Settings** (backend chips, model card, live-ranking
  big toggle surface, about line). No navigation dependency: one-level pushed List screen + custom pill
  tab bar; data is local stub data for later parser/ranker cards.
- Launcher icon: adaptive icon (solid #10261C background, hand-written vector list+tick foreground, mono
  layer), same pattern as Bonsai; no material-icons dependency. Manifest is platform NoActionBar theme,
  CAMERA + INTERNET permissions, label "ScanList".
- Throwaway debug keystore: `apps/kotlin/app/scripts/make-debug-keystore.sh` (adapted from Bonsai's
  `scripts/make-debug-keystore.sh`) writes `apps/kotlin/app/.signing/debug.jks` (PKCS12, alias
  `scanlist`, password `android`, CN "ScanList Kotlin debug"). `.signing/` is gitignored by
  `apps/kotlin/app/.gitignore` (verified with `git check-ignore`); **no keystore is in git**. The module
  uses it only when present and otherwise falls back to AGP's debug key, so CI needs no keystore and no
  Gradle file contains a host path.
- `apps/kotlin/build.sh` — repo-root-driven build entry point: cds to the worktree root, sources
  `scripts/android-env.sh`, generates the keystore if missing, then runs `scanlist_gradle` (shared slot
  lock + aarch64 aapt2) with `:scanlistKotlin:assembleDebug` by default; extra args are passed through as
  Gradle tasks. Does not touch `.github/` — the existing `pr.yml` already runs
  `./gradlew --no-daemon :scanlistKotlin:assembleDebug`, which matches this module.
