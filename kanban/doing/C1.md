# C1 — Web server skeleton (FastAPI) with fake embedder

## Do
Python FastAPI + uvicorn, venv in apps/web/server/.venv (gitignored). Endpoints: GET /health, POST /embed/text
{texts, kind: doc|query} → 256-d vectors, POST /embed/image (jpeg body) → vector, GET /off/{barcode}

frontend from apps/web/frontend/dist.

### 2026-11-16 — review fixes (ag-c1, PR #5: REQUEST-CHANGES → both applied)

Adversarial review found two real defects; everything else passed (determinism, OFF proxy TTL/privacy, scope,
34 tests reproduced).

1. **CI red — pytest missing from runtime requirements.** CI `Server tests` (`.github/workflows/pr.yml`, lead-owned,
   untouchable) does `python3 -m venv .venv-ci` → `pip install -r requirements.txt` → `python -m pytest -q` in a
   fresh venv, so `pytest` must be a *runtime* requirement (run 43943054577: "No module named pytest").
   Fix: added `pytest>=8` to `requirements.txt` (kept `requirements-dev.txt` as a convenience alias).
2. **User input → 500.** `BARCODE_RE.match(barcode)` accepted `"12345678\n"` (Python `$` also matches before a
   trailing newline), the barcode reached httpx, and `httpx.InvalidURL` (not an `httpx.HTTPError` subclass)
   escaped the handlers → uncaught 500. Verified locally before/after: `GET /off/12345678%0A` was `500`
   (0 upstream hits) → now `422` with `barcode must be 8-14 digits...`.
   Fix: `BARCODE_RE.fullmatch(...)` in `is_valid_barcode()` + belt in the `/off/{barcode}` handler
   (`except (ValueError, httpx.InvalidURL)` → 400). Regression test
   `test_barcode_with_trailing_newline_is_rejected_not_500` parametrised over `%0A`, `%0D%0A`, leading `%20`,
   trailing `%20`, asserting 4xx and zero upstream requests.
3. Nit applied while there: `TODO(C3)` comment in `app/main.py::embed_text` — real embedder calls must go through
   `anyio.to_thread` (sync CPU work inside `async def` stalls the loop) and each text needs a length cap.
