Then **Server tests** (card C1/C3's code) failed:

```
FAILED tests/test_embed_api.py::test_root_is_friendly_without_a_built_frontend
json.decoder.JSONDecodeError: Expected value: line 1 column 1 (char 0)
  body = '<!doctype html>…<div id="app"></div>…'
```

Cause: that test calls `create_app()` with **no** `frontend_dist`, so it resolves
`DEFAULT_FRONTEND_DIST = apps/web/frontend/dist` (`apps/web/server/app/main.py:27`). CI builds the
frontend in the same job **before** running pytest, so `/` correctly returns `dist/index.html`, not
`{"frontend": "not built"}`. My card is what makes that directory exist — but the assumption (an
implicit global path) is in `apps/web/server/tests/test_embed_api.py`, which is **not in my owns**.
`main`'s web job never hit it because `apps/web/frontend/` did not exist there yet.

Suggested one-line fix for the server card/lead (verified against the resolver, `main.py:180-183`:
`dist.is_dir() and (dist / "index.html").is_file()` — anything else returns `None`):

```python
def test_root_is_friendly_without_a_built_frontend(tmp_path) -> None:
    with TestClient(create_app(frontend_dist=tmp_path / "missing")) as client:
        response = client.get("/")
    assert response.status_code == 200
    assert response.json()["frontend"] == "not built"
```

(`test_unknown_api_path_is_404_without_frontend` has the same hidden dependency but passes either way,
because the mounted `StaticFiles` also 404s unknown paths.) Alternative, if the workflow owner
prefers: run the server tests before the frontend build step in `.github/workflows/pr.yml` — but the
test should not depend on the checkout's build state either way. I did **not** edit `apps/web/server/`
or `.github/` (other tracks / lead-owned).

So: my card's Done-when (test + build + tsc) is green locally **and** in CI; the PR is red only on
the C1 test above. Nothing else blocked.
