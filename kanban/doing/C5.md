### C5 implementation note 2026-11-17 (ag-c5)

**What landed** — `apps/web/frontend/src/scan/ui/` (owned):
- `controller.ts` evidence windows → `pool.ts` → `ranking.ts` (`evaluateTick` → ts-core `rank()`/`decideTop()`); never calls `onToggle`.
- `pool.ts` **pool-order decision (required by the card)**: the barcode query text is always slot 0
  and OCR is capped at `MAX_TEXT_QUERIES - 1` (15) while OFF returned a usable name, so a barcode
  found *after* 16 OCR lines can never be evicted by the ranker's arrival-order cap of 16. A
  barcode that resolves to no name does not consume a slot. **No rank-side (ts-core) change**; the
  cap is applied client-side and proven by `pool.test.ts` + `controller.test.ts`
  ("keeps a barcode that arrives AFTER 16 OCR lines").
- `textEmbedder.ts` / `offClient.ts`: synchronous ports over `POST /embed/text`, `POST /embed/image`,
  `GET /off/{barcode}`; cache per raw text, one background batch per kind, `onSettled`/`onResolved`
  re-ticks. Prefixes come from `shared/spec/prompts.json` via `?raw` (`prompts.ts`), never hard-coded.
- `ScanScreen.tsx` / `ScanResults.tsx` / `scan.css`: camera top, nullable hero from `topId`, source
  chips, ranked rows, FLIP reorder (`flip.ts`, translate-only, reduced-motion respected), manual
  tick via C2's `onToggle` using the ORIGINAL `ScanListItem` (`items.ts` id→item map), 400 ms tick.
- `vibrate.ts`: `navigator.vibrate` start/tick/reject patterns with a graceful no-vibrate path.
- OCR defaults ON in the screen (C4 source stays opt-in when no engine); toggling restarts the
  single-use session. No list → no camera access, honest "NO LIST OPEN" card.
