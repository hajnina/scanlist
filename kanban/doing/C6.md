### Idempotency / process hygiene (per AGENTS.md: no `pkill -f`/`pgrep -f`)
- Per-checkout run dir `$RUN_DIR=/tmp/scanlist-web-$(sha256 of checkout path | cut 8)` — never inside
  the repo, so concurrent worktrees do not collide. PID files for uvicorn and caddy, plus a file
  recording the `tailscale serve --https` port this script added.
- Re-run stops *only* its own recorded PIDs (verified via `/proc/<pid>/cmdline` so PID reuse after a
  reboot cannot make it kill a stranger), then starts fresh. `--stop` also removes only its own
  tailscale serve mapping; the two pre-existing mappings on this machine (`:443`→8000, `:8443`→9000)
  survived `--stop` untouched (checked with `tailscale serve status` before/after).
- If the port is held by something the script did not start it refuses and exits 1 without touching it
  (tested against another agent's uvicorn on :8765 — it kept running, pid 3480955).

### Notes for the lead
- Default HTTPS port is 8444, not 443, on purpose: this machine already had someone else's
  `tailscale serve` mappings on `:443` and `:8443`, so the script uses its own port and `--stop`
  provably leaves theirs alone. If a cleaner URL is wanted later, `--https-port 443` works but will
  replace whatever is on that port.
- `tailscale serve` needs HTTPS certificates + MagicDNS enabled for the tailnet; if that is ever off,
  the script falls back to Caddy, and without Caddy it fails loudly with a pointer to DEPLOY.md rather
  than silently serving plain HTTP (a silent http:// would look like "the camera is broken").
- No CI impact expected: this card only adds a shell script and Markdown; nothing under `.github/`,
  no gradle change.
