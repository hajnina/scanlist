## Notes

### What I did (ag-s6, 2026-11-16)

Added `scripts/model.sh` — the only file this card owns (plus this Notes section). ~330 lines, bash, `set -euo pipefail`,
no dependencies beyond `curl` (via the housekeeper downloader), `sha256sum`, `stat` and `adb`.

```
scripts/model.sh fetch  [--force] [--detach]   download + verify (resumable, sha256)
scripts/model.sh verify [--quiet]              re-check the local file
scripts/model.sh path                          print the local model path
scripts/model.sh push <package> [options]      put ONE file into the app's own files dir
```

**Constants come from the HF tree API, not from docs** (card instruction). Read 2026-11-16 with
`curl -sL https://huggingface.co/api/models/litert-community/embeddinggemma-2-740m-litert-lm/tree/main`:

```json
{"type":"file","size":484622336,
 "lfs":{"oid":"e7a8a2204b91e0f96e92960e84a09a89212e1633dcb7575a9bf3378b4df77f4c","size":484622336,...},
 "path":"embeddinggemma-2-740m.litertlm"}
```

→ pinned in the script: `MODEL_SIZE=484622336`, `MODEL_SHA256=e7a8a220…f4c`,
`MODEL_URL=https://huggingface.co/litert-community/embeddinggemma-2-740m-litert-lm/resolve/main/embeddinggemma-2-740m.litertlm`.
Same values as RECIPE.md §3 — no drift. Other bundles in the repo (Tensor G5/G6, Qualcomm, …) are deliberately not handled:
RECIPE §7 says GPU+CPU is the shippable pair, so this script provisions exactly the CPU/GPU bundle.

- `fetch`: checks the local file first (missing / incomplete / wrong-sha / ok); **ok → exits 0 without downloading**
  (idempotent, safe to call from every track's setup script); incomplete → resumes; wrong sha at the right size →
  deletes and re-downloads; `--force` restarts from zero. Calls
  `~/housekeeper/scripts/resumable-download.sh URL DEST SIZE SHA` (the hard-rule downloader: `curl -C -`, retries
  forever, exits 2 on size/sha mismatch), tees its output to `~/models/scanlist/fetch.log`, then runs its **own**
  size+sha check as a second opinion. `--detach` runs it with `nohup` (prints pid + log path; hard rule for a 484 MB
  download) — the default is foreground so `fetch` returning 0 means "verified".
- `verify` / `path`: cheap states (`missing` / `incomplete` / `wrong sha` / `ok`) without re-hashing a short file;
  exit 3 when the local model is not usable. `path` is for the Kotlin/RN tracks and benches (S5/X*) so nobody
  hard-codes the model path.
- `push <package>`: copies `references/embeddinggemma/scripts/pixel8/push_model.sh`'s intent and adds the ownership
  rule from RECIPE §3 / gotcha 3 — **never `adb shell mkdir` the target dir**:
  1. requires the app's own dir to exist (`/sdcard/Android/data/<pkg>/files`), else exits 4 telling you to launch
     the app once (that is what makes the dir app-owned),
  2. pushes **only the file** (never the folder — the `models/models/` trap) into `/data/local/tmp`,
  3. `run-as <pkg> mkdir -p <app>/…/models` + `run-as <pkg> cp <staging> <final>` so the copy is app-owned
     (fallback for non-debuggable builds: single-file `adb push` into the app-created dir — RECIPE's own workaround,
     with a warning that the dir must be app-owned),
  4. `sha256sum` **on the device**, compares with the pinned sha, exits 4 on mismatch (with a hint about the
     "Failed to open LiteRT-LM file" ownership symptom), then deletes the staging file.
  `--dest external` (default) = `/sdcard/Android/data/<pkg>/files/models/embeddinggemma-2-740m.litertlm` — the layout
  MnemoThera uses; `--dest internal` = `run-as <pkg>` → `files/models/…`; `--dest both`; `--serial <S>`; `--no-verify`.
  Push always verifies the local model first (exit 3) and that `pm path <pkg>` is non-empty (exit 4).

### Push is implemented but **untested on device** (card instruction — no phone on adb)

`adb devices` is empty on this laptop, so no real device run happened. To still test the whole push code path offline I
put a stub `adb` on PATH (`/tmp/opencode/stub-adb/adb`, not committed — not in `owns:`) that simulates one device, an
installed package, an app-created external dir, a working `run-as`, and a mirror filesystem so `sha256sum` on the
"device" is a genuine check. Results:

| case | behaviour |
|---|---|
| `--dest external` (debuggable) | `push` file → `/data/local/tmp` → `run-as mkdir -p /sdcard/Android/data/<pkg>/files/models` → `run-as cp` → on-device sha OK → staging deleted |
| `--dest internal` | same, into `run-as <pkg> files/models/` → on-device sha OK |
| `--dest both` | both trees written, both sha-checked |
| no `run-as` (release build), dir exists | warning + single-file `adb push` into the app-created dir + `adb shell sha256sum` OK |
| corrupt transfer | exit 4 with got/want sha + the ownership hint |
| app not installed | exit 4 `… is not installed on …` |
| `/sdcard/Android/data/<pkg>/files` missing | exit 4 telling you to launch the app once; **never** mkdirs as shell |
| wrong `--serial` | exit 4 listing attached serials |

The stub log shows the exact adb command sequence, and no `adb shell mkdir` ever appears. **Still needs one real run**

### Notes / decisions for the lead

- Weights stay outside git: `~/models/scanlist/embeddinggemma-2-740m.litertlm` (+ `fetch.log`), nothing in the repo.
- `<package>` = the Android application id (e.g. `dev.hajnina.scanlist.kotlin`), not an APK.
- Default `--dest external` follows RECIPE §3 (MnemoThera reads `getExternalFilesDir(null)/models/…`). **B1/B2 must
  use `<externalFilesDir>/models/embeddinggemma-2-740m.litertlm`** (or say otherwise and call `--dest internal`).
- `run-as` only works for debuggable builds; for a release APK the app has to create its own dirs on first launch,
  then the single-file `adb push` fallback is used. `push` verifies the on-device sha either way.
- NPU/NPU-AOT bundles are out of scope (RECIPE §7: GPU+CPU ships); adding another bundle means new pinned
  size/sha constants, which this script deliberately does not guess.
- No `.github/` or CI change: it is a laptop-side script, CI never runs it (no model weights, no network in CI).
- Shellcheck is not installed on this laptop; `bash -n` passes and every branch above was executed.
