### What I did (ag-s7, 2026-11-16)

Added `scripts/android-env.sh` — the only file this card owns. Sourced, it exports the aarch64 toolchain env the
same way `references/bonsai-ui/src/bonsai-serve/build.sh` does, and caches nothing: no writes anywhere, no sudo,
no toolchain modification.

- `ANDROID_TOOLCHAIN` (default `~/projects/martins-whisper/android-toolchain`, overridable) →
  `JAVA_HOME=$T/jdk` (Temurin 17), `ANDROID_HOME`/`ANDROID_SDK_ROOT=$T/sdk`, `GRADLE_USER_HOME=$T/gradle-home`,
  `GRADLE_BIN=$T/gradle/current/bin/gradle` (falls back to `gradle-8.9/bin/gradle`).
- build-tools: newest installed version dir (`SCANLIST_BUILD_TOOLS` overrides) = 35.0.1, added to PATH.
- **aarch64 aapt2 override** (`$ANDROID_HOME/build-tools/35.0.1/aapt2`, verified `ELF 64-bit aarch64`), exported as
  `ANDROID_AAPT2` and wired two ways: `GRADLE_OPTS=-Dorg.gradle.project.android.aapt2FromMavenOverride=<aapt2>`
  (Gradle turns `-Dorg.gradle.project.*` into project properties, so a plain `./gradlew …` works too — verified),
  and the helper `scanlist_gradle` adds `-Pandroid.aapt2FromMavenOverride=<aapt2>` (Bonsai's exact form).
  `scanlist_gradle` runs through the shared `owner/tools/gradle-slot.sh` lock + `--no-daemon` when that exists
  (several agents build in parallel on this laptop), else plain `gradle --no-daemon` (CI).
- NDK: `ANDROID_NDK=$T/sdk/ndk`, `ANDROID_NDK_HOME`/`ANDROID_NDK_ROOT`/`NDK_HOME` → 27.0.12077973 (AGP 8.7's
  default; `SCANLIST_NDK_VERSION` overrides, 30.0.16248370 is also installed). **Caveat:** these NDKs only ship a
  `linux-x86_64` prebuilt LLVM toolchain, so native CMake/ndk-build on this aarch64 host is still unproven
  (Kotlin/Java modules are unaffected). Tracked in the toolchain's own STATUS.md as well.
- PATH gets jdk/bin, gradle bin, platform-tools, build-tools/35.0.1, cmdline-tools/latest/bin, de-duplicated.
- CI-safe: if `$ANDROID_TOOLCHAIN` is absent (x86_64 ubuntu runner) it prints one note to stderr and leaves the
  environment untouched → CI uses the normal SDK + Maven aapt2, nothing laptop-specific leaks into gradle files.
- Idempotent (source twice = identical env, no duplicate PATH/`GRADLE_OPTS` entries), safe under `set -euo pipefail`,
  quiet when sourced, prints a summary when run as `bash scripts/android-env.sh`. Warns (doesn't override) if a
  non-toolchain `JAVA_HOME` is not JDK 17.

### Usage for other cards (A1/B*, S5)

```sh

RC/RN note for A1: `ANDROID_HOME`, `ANDROID_SDK_ROOT`, `JAVA_HOME`, `ANDROID_NDK_HOME`, `ANDROID_AAPT2` are all
exported; pass the aapt2 override as `-Pandroid.aapt2FromMavenOverride=$ANDROID_AAPT2` if a tool of yours ignores
`GRADLE_OPTS`, and set `CMAKE_MAKE_PROGRAM=$ANDROID_HOME/cmake/<ver>/bin/ninja` only if CMake is needed.

`build-tools/` contains **two** dirs (34.0.0 and 35.0.1), so the glob expands to two words and aapt2 reads the

```

Pinning the dir the script exports passes (`$ANDROID_HOME/build-tools/$SCANLIST_BUILD_TOOLS/aapt2 version` →

`scripts/` can change how many build-tools dirs the shared toolchain holds, and the toolchain is read-only for us).

### README section — please place this (README is outside S7 `owns`)

```markdown
## Android builds (aarch64 laptop)

This machine is aarch64, so the x86_64 aapt2 that Gradle downloads from Maven cannot run. Instead of hacking
`gradle.properties`, every build sources one script that points at the shared toolchain in
`~/projects/martins-whisper/android-toolchain` (Temurin 17, Gradle 8.9, SDK platform 35, an aarch64 aapt2):

```sh
source scripts/android-env.sh

scanlist_gradle :app:assembleDebug   # recommended: shared build-slot lock, --no-daemon, aapt2 override
./gradlew :app:assembleDebug         # also works, the override arrives as a Gradle project property
```

It exports `JAVA_HOME`, `ANDROID_HOME`/`ANDROID_SDK_ROOT`, `ANDROID_NDK_HOME`, `GRADLE_USER_HOME`, `GRADLE_BIN`,
`ANDROID_AAPT2` and `GRADLE_OPTS=-Dorg.gradle.project.android.aapt2FromMavenOverride=<aarch64 aapt2>`, and adds the
JDK, Gradle, adb and build-tools to `PATH`. Overrides: `ANDROID_TOOLCHAIN`, `SCANLIST_BUILD_TOOLS`,
`SCANLIST_NDK_VERSION`, `GRADLE_USER_HOME`. Sourcing it twice is harmless, and on a normal x86_64 machine (CI) it
does nothing except print a note — laptop-only settings never live in the Gradle files.
Native (NDK/CMake) builds are **not** supported on this host yet: the installed NDKs only contain a linux-x86_64
prebuilt toolchain. `bash scripts/android-env.sh` prints what was resolved without exporting it.
```

### Risks / follow-ups

- The aapt2 override arrives via `GRADLE_OPTS` and via `scanlist_gradle -P`; both verified with a scratch Gradle
  project. If a future build clears `GRADLE_OPTS` (some wrappers do), use `scanlist_gradle` or pass
  `-Pandroid.aapt2FromMavenOverride="$ANDROID_AAPT2"` explicitly.
- NDK native builds remain blocked on this host (linux-x86_64 prebuilts only) — relevant to a future native
  embedding module, not to Compose/RN-JS-only builds.
- No secrets/keystores/weights added; `scripts/android-env.sh` is 100% paths + flags and contains no machine
  secrets (only the absolute default toolchain path, same as Bonsai's build.sh, overridable).
