### Decisions / divergences, for review

1. **TypeScript is a second devDependency.** Card said vitest as the only dev dep, but the required
   `npx tsc --noEmit` resolves the unrelated `tsc@2.0.4` wrapper when TypeScript is absent (I hit
   that: "This is not the tsc command you are looking for"). `typescript@5.9.3` is dev-only; there
   are still **zero runtime deps**. CI only runs `npm test`.
2. **RANK.md on main has only the 0.02 hysteresis**, no margin M / threshold T in `rank()` or
   `decide_top` yet (checked: `git diff origin/main -- shared/spec/RANK.md` empty; the constants in
   `PREFIX_AB.md` are recommendations for S10). I implemented the current oracle behaviour and
   isolated `decideTop` with a `TODO(S10)` so S10's margin/threshold/image-guard amendment edits one
   function. Golden top-3 is unaffected.
3. **docText path segments** follow the Python oracle (`scanlist_ref.py::doc_text`) exactly, which
   does not re-trim `path` segments; FLATTEN.md §4's `path' = trim(s)` is a no-op for all committed
   sample/section names. If S1 wants literal per-segment trimming, the oracle and this port must
   change together.
4. **Alias/barcode case folding** uses NFC + `String#toLowerCase()` (with a NOTE): Python
   `casefold()` maps e.g. `ß`→`ss`, which `toLowerCase` does not. Same approximation as Kotlin's
   `lowercase(ROOT)`; S10's pending RANK.md amendment should pin one rule for all three tracks.
   All committed data/samples/golden are unaffected.
5. **`version`**: JS `JSON.parse` cannot distinguish `1` from `1.0`, so both are accepted as integer
   (JSON Schema also accepts 1.0); B2's Kotlin `toIntOrNull` rejects `1.0`. Huge integers beyond
   Kotlin's Int range are also accepted here. No spec/golden case depends on either; noted rather
   than adding a raw-token parser.
6. `.gitignore` already covers `shared/ts-core/node_modules` via the root `node_modules/` pattern
   (`git check-ignore -v` verified); no change needed.
