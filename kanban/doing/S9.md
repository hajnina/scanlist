### Notes for the lead
- **CI hook already exists, no `.github/` edit needed for S5**: the `shared` job in
  `.github/workflows/pr.yml` (lines 61-66) checks for root `gradlew` + `settings.gradle.kts`, then runs
  `./gradlew --no-daemon :shared:android-embed:assembleDebug :shared:android-embed:testDebugUnitTest`.
  That exact path is what this card's `settings.gradle.kts` provides, so S5 will be built by CI as soon as
  `shared/android-embed/build.gradle.kts` lands. I did not touch `.github/` (lead-owned).
- **`:scanlistKotlin` must not pin plugin versions**: root pins them; a version in a module build file makes
  Gradle fail with "plugin request already on the classpath must not include a version". I put this in
  `build.gradle.kts` comments and in the PR body for B1.
- **B1 CI risk (lead-owned `.github/workflows/pr.yml`)**: the `kotlin` job (lines 79-84) runs
  `working-directory: apps/kotlin` and *requires `apps/kotlin/gradlew`*, which B1's `owns:` does not include.
  With this root build, B1's build is `./gradlew --no-daemon :scanlistKotlin:assembleDebug` from the repo root
  (APK at `apps/kotlin/app/build/outputs/apk/debug/*.apk`). Suggest switching that job to the root wrapper when
  B1 lands, otherwise B1's PR will be red for a reason that is not B1's code. (`rn`/`web` jobs unaffected.)
- **Laptop toolchain regression in `scripts/android-env.sh` (S7-owned, NOT mine to edit)**: the shared SDK now
  also has `build-tools/37.0.0`, whose `aapt2` is **x86_64**; the script's "newest build-tools dir" heuristic
  therefore exports an x86_64 aapt2 and any local Android module build dies with
  `AAPT2 37.0.0 Daemon #0: Daemon startup failed`. Workaround for now:
  `export SCANLIST_BUILD_TOOLS=35.0.1; source scripts/android-env.sh` (35.0.1 and 34.0.0 are aarch64).
  Better fix in the script: pick the first build-tools dir whose `aapt2` is aarch64 / pin 35.0.1.
  It does not affect this card's Done-when (no aapt2 needed) and does not affect x86_64 CI.
