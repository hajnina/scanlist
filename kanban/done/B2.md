**Decisions worth a reviewer's eye**
- **kotlinx.serialization without the compiler plugin.** The card names kotlinx.serialization; the plugin
  pin would have to live in the root `build.gradle.kts` (S9-owned, "plugin pins are root-owned" per the
  B4 lead note). Using only the `JsonElement` **tree** API needs the runtime (`kotlinx-serialization-json
  :1.7.3`) and no plugin, so nothing root-owned changes; it also preserves the number-vs-string amount
  union exactly. Both deps pinned at module level (`junit:junit:4.13.2` for the tests).
- **JSON file per list, not DataStore** (card allows either): the artifact is a JSON document, the file is
  the export format, zero new dependencies and the whole persistence layer is JVM-testable.
- **Share = ACTION_SEND text** (plus SAVE via `ACTION_CREATE_DOCUMENT`, plus COPY): the alternative
  (ACTION_SEND with a `content://` URI) needs a FileProvider entry in the manifest, which is outside this
  card and would have meant editing B4's/lead-owned manifest. JSON is plain text, so the text extra is lossless.
- Warnings recommended by LIST.md §5 (duplicate explicit id, unknown keys, unit-without-amount, untrimmed
  name) are **not** surfaced yet — they are SHOULD-level and the parser already tolerates all four; a
  candidate for B7's error/empty-state pass.
