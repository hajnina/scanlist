**Card done.** Kotlin port of RANK.md §1–§9 plus the on-list-open item-vector pipeline that feeds it

**What landed** — package `dev.hajnina.scanlist.kotlin.rank`
(`apps/kotlin/app/src/main/java/dev/hajnina/scanlist/kotlin/rank/`), self-contained, no UI state:

- `Rank.kt` — pure port of `shared/ref/scanlist_ref.py`'s `rank()`/`q6()`/`decide_top()`/`unranked()`
  with **float64 everywhere**: per-source max over queries → max across sources (never mean), cosine
  clamp + q6 per query, barcode exact-match boost +0.15 on `raw` before the EMA, EMA α = 0.5 once per
  tick, q6 rounding, tie → flatten order, hysteresis > 0.02 (strict), output = top, rest, done group.
  §8 degraded states: no signal → unranked + cleared state; missing/wrong-dim/NaN item vectors →
  previous output unchanged; all checked → ranked, `topId = null`, done group; zero items; zero query
  (cosine 0.0); NaN/Inf and wrong-dim query vectors dropped; text queries capped at 16. Also
  `truncateAndNormalize()` (truncate **then** normalise, zero vector stays zeros) and `normBarcodeText()`.
- `RankTicker.kt` — §7 lifecycle, mirroring the Python `RankTicker`: `submit` (latest frame wins),
  `tick` (400 ms gate, caller-supplied monotonic ms so tests don't sleep), `tickNow`, `listChanged`,
  `scanStarted`, `scanStopped` (unranked + queries/state cleared).
- `ItemVectorCache.kt` — RANK §2.1 disk cache, key = lowercase sha1 of
  `"scanlist-item-vector/1\n" + model + "\n" + dims + "\n" + docPrefix + "\n" + docText`, one binary
  file per docText under an app-private dir (`ItemVectorCache.defaultDir(filesDir)` =
  `filesDir/vectors/item-vectors`), 256 **float64** values (float32 storage would perturb a golden
  vector before the ranker saw it), atomic write (temp + fsync + rename), per-session hot map,
  corrupt/foreign file ⇒ miss + delete + rewrite. Model/dims/prefix change invalidates by construction.
- `VectorSource.kt` — the float64 embedding seam plus `EmbedderVectorSource`, the only adapter that
  imports `shared/android-embed` (S5): `embedDocs`/`embedQuery`/`embedImage` widened float32→float64.
- `ItemVectorIndex.kt` — cache-aware embedding: unique docTexts, cache hits never touch the model,
  misses in batches (`batchSize` 8), progress callback per batch (`EmbedProgress`), `shouldStop`
  between batches, broken vectors reported as failed and never cached; items sharing a docText share
  one vector/one entry.
- `ListEmbedding.kt` — Android/Compose edge: process-wide `EmbeddingRuntime` (one `Prompts` load, one
  `Embedder`, one `ItemVectorIndex`), model at `<files>/models/embeddinggemma-2-740m.litertlm`
  (missing ⇒ clear non-fatal FAILED state, list still opens unranked), and
  `rememberListEmbedding(context, listId, items)` running the index on `Dispatchers.IO` with progress as
  Compose state. Plus `List<FlatItem>.toRankItems(vectors)` for the scan UI (card B5).
