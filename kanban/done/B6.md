## Notes

### What landed (card B6)

New package `dev.hajnina.scanlist.kotlin.settings` (all under `owns:`):

- `BackendChoice.kt` — the four picker options Auto / GPU / CPU / NPU(experimental) mapped onto
  shared/android-embed's `EmbedBackend` ladder: Auto = GPU→CPU (the shipped order), GPU/CPU/NPU are
  strict single-backend ladders so the probe reports a GPU failure instead of silently measuring the
  CPU and labelling it "GPU"; NPU is `allowNpu = true`, marked experimental, and never in Auto
  (RECIPE.md §7: SM8750 bundle fails on 0.18.1/0.19.1, JIT 140–236 s).
- `SettingsStore.kt` — the choice persisted at `filesDir/settings/embedding.json`, atomic tmp+rename,
  plain `java.io` + kotlinx-serialization like B2's `ListStore` (no DataStore dependency for a few
  bytes; a missing/corrupt file reads as Auto and never throws).
- `ModelStatus.kt` / `ModelProbe` — status of the bundle the pipeline actually opens
  (`rank.defaultModelFile` = `<filesDir>/models/embeddinggemma-2-740m.litertlm`, B3), with
  `E_NO_MODEL`, present + size vs the pinned 484,622,336 B, unreadable/empty reasons, the pinned
  sha256 and the `scripts/model.sh push --dest internal` hint. Sha is not recomputed per visit.
- `PrefixInfo.kt` — active prefix set + doc/query/image prefixes from the bundled `prompts.json`
  (mnemothera, trailing spaces named), nothing hard-coded.
- `Latency.kt` — `SelfTestRunner`: open the picked backend, warm up once (engine load), embed 3 fixed
  sample docs one call at a time, report per-call + mean + load + real backend + supportsImages.
  Re-runs on every backend switch / "test again" → the card's Done-when on device. Embedder is
  opened and closed per run.
- `SettingsState.kt` — thin Compose state holder (persist, clear stale numbers on switch, model
  probe, prefix load) + `rememberSettingsState()` device wiring.
- `SettingsScreen.kt` — M3 Expressive screen: backend chips + active-backend line, latency hero card
  (mean, per-call, load, E_NO_BACKEND/E_NO_MODEL/E_EMBEDDER with reasons), model card (path, size,
  status, sha256, push hint), prefix card, the B1 live-ranking toggle kept as-is.

Tests (new, `apps/kotlin/app/src/test/.../settings/`): BackendChoiceTest 8, SettingsStoreTest 7,
ModelStatusTest 8, PrefixInfoTest 5, LatencyTest 4, SelfTestRunnerTest 8, SettingsStateTest 7 = **47**
new tests, all with fake embedder/clock or temp dirs (no device, no weights).

### Not done / honest limits

- Switching a backend re-embeds the three settings samples, not the open list: the app-wide
  `AppEmbedding` runtime (rank/**) builds its embedder with the default config and is B3-owned. A
  later card should make rank read `SettingsStore` so a switch also re-embeds lists; B6 must not
  touch rank/**. Disclosed in the PR.
- The self-test opens its own embedder and closes it; if a list's rank runtime is resident, the two
  engines can briefly compete for memory (documented in `SelfTestRunner` KDoc).
- No SERVER option: the in-process `EmbedBackend` enum has no server backend (NPU/GPU/CPU only);
  showing a dead chip would be dishonest.
