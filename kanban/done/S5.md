### Builder log (ag-s5), 2026-11-16/17
**What landed** — `shared/android-embed/` (Android library, namespace `dev.hajnina.scanlist.embed`, minSdk 31 /
compileSdk 35, JVM target 17), picked up by S9's root `includeIfExists(":shared:android-embed", …)`; no plugin
versions in the module (root pins AGP 8.7.3 / Kotlin 2.0.21).

- `Embedder.kt` — `embedDoc*`/`embedQuery`/`embedImage` + `backend`, `dims`, `modelId`, `supportsImages`
  (the ARCHITECTURE.md contract plus images), exceptions (`NoBackendException`, `EmbeddingUnavailableException`).
- `Vectors.kt` — Matryoshka truncate → L2 normalise (256 default, read from prompts.json), cosine with the
  reference's −1 sentinel. `Prompts.kt` — reads bundled `assets/prompts.json` (verbatim copy of
  `shared/spec/prompts.json`, byte-identical, `active = modelcard`); nothing hard-codes a prefix.
- `GoldenVectors.kt` + `assets/embed_golden.json` — verbatim copy of MnemoThera's asset, sha256-keyed,
  `MIN_COSINE = 0.98`. `SelfTest.kt` — ranking check **and** cosine-vs-CPU-reference proof per backend.
- `BackendHealth.kt` / `BackendLadder.kt` — GPU → CPU, NPU only behind `allowNpu`; strikes (2 unproven /
  3 proven), CPU never blocked, clean close forgives, SharedPreferences store, per-model keys.
- `LiteRtEngineFactory.kt` — real LiteRT-LM `EmbeddingEngine` (`ModelInfo.from`, `visionBackend`,
  `InputData.Image`, per-input-length cache dir); `LiteRtEmbedder.kt` — in-process default + `create(context, …)`.
- `RemoteEmbedder.kt` / `EmbedService.kt` / `EmbedIpc.kt` + manifest `:embed` service — separate-process option,
  **default stays IN_PROCESS** (`Embedders.create(..., ProcessMode.IN_PROCESS)`).
- `README.md` — API, ladder/strike table, provenance, version decision, what still needs a phone.
- Copy-first honoured: every ported file names its `references/embeddinggemma/src/...` (MnemoThera) or
  Google AI Edge Gallery origin in the header; `consumer-rules.pro` keeps `com.google.ai.edge.litertlm.**`.

**LiteRT-LM version decision: 0.18.1 (not 0.19.1).** The card's research verified the vision API in 0.19.1;
`javap` on both local Maven AARs shows 0.18.1 already carries the identical shape
(`EmbeddingEngineConfig(modelPath, backend, visionBackend, audioBackend, cacheDir, modelFd, maxInputLength,
visionTokensPerImage, activationDataType)`, `EmbeddingOptions(normalize, insertSpecialTokens, outputSize,
visionTokensPerImage)`, `InputData.Image`), and 0.18.1 is the version MnemoThera measured on three phones
(RECIPE.md §1/§6/§7). No bump; image support is used, not gated. Caveat: 0.18.1's metadata is Kotlin 2.4 vs the
repo's 2.0.21, so the module compiles with `-Xskip-metadata-version-check` (compile-time only; the clean fix is a
lead-owned root Kotlin bump).
