### Lead note 2026-11-17 (C3 merged — the image-latency asymmetry is a headline finding for you)
- The web track's image embedding is **6.4–11.9 s/frame** on the fp32 CPU path (PERF.md), vs text ~400–500 ms cold / 0 ms cached. The Kotlin/RN tracks embed on-device (LiteRT). When you benchmark the three tracks, image-query latency is the expected headline divergence; treat web image queries as on-demand (the C-track scan UX must, too). The parity numbers are bitwise-grade (min cos 0.999999999996, 146/146) — accuracy should NOT be a differentiator; latency is.
