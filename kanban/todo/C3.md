### Lead note 2026-11-16 (research digest: web-rn-runtime-prior-art.md)
- llama.cpp DOES embed images now: PR #30054 merged 2026-10-06 (first tag containing it: b11454 — anything older fails `unknown model architecture: 'gemma-embedding2'`). Serve via `llama-server`: `POST /v1/embeddings` with NESTED typed parts `{"input":[{"content":[{"type":"image_url","image_url":{"url":"data:image/jpeg;base64,..."}}]}]}`. TRAP: `POST /embedding` with `image_data` returns HTTP 200 with a TEXT-ONLY vector (cos 1.0000 between different images) — never use it. GGUF: `ggml-org/embeddinggemma-2-GGUF` (Q8_0 + mmproj); user-measured ~200 ms/image on a small x86 CPU (9 images / 1.8 s, single stream).
- TEI is text-only (issue #333 open since 2024) — dead end for images. Pure-Python option: sentence-transformers + FastAPI with `SentenceTransformer("google/embeddinggemma-2", config_kwargs={"audio_config": None})` → 440M params; joint via `encode({"text": "... นิ ...", "image": [...]})`; text via `truncate_dim=256, normalize_embeddings=True`. Precision: bf16 or fp32 on CPU, NEVER fp16 per the PyTorch model card (the ONNX card reports fp16 fine — server follows the PyTorch rule).
