## Notes

### Lead note 2026-11-16 (research digest: web-rn-runtime-prior-art.md)
- BarcodeDetector: stable in Chrome Android since v83 (requires Google Play Services), NOT in Firefox, flag-gated in Safari, absent on desktop Linux Chrome — feature-detect via `getSupportedFormats()` and bundle zxing-wasm `reader` (~1.04 MiB, MIT) as fallback, or use the `@sec-ant/barcode-detector` polyfill for one code path.
- Frame cadence guidance from 2026 writeups: copy the video frame to a canvas every ~150 ms, `getContext('2d', {willReadFrequently: true})`.
- Build the frame sampler so the JPEG can go EITHER to `/embed/image` (server, C3) OR to an in-browser embedder (spike card C7) — keep the choice behind an interface, the C7 spike may flip it.

### Lead note 2026-11-17 (C3 merged — frame-upload cadence + deferred server nits)
- **Image upload cadence**: server-side image embedding costs 6.4–11.9 s/frame (fp32 CPU, PERF.md). Do NOT upload per camera frame (~2.5 fps) — the queue would back up forever. Design: opportunistic single-frame uploads (e.g. one in-flight image request, newest-frame-wins, or a ~5–10 s cadence), while barcode/OCR text queries stay cheap. The server caps: 2048-char/512-token inputs, LRU 4096.
- Deferred C3-review code nits (low, apply if you touch these files): `app/main.py:110` error body `{"error":{...}}` vs C1's `{"detail":...}` (doc-only for now, README notes it); `last_latency_ms` is shared state — concurrent requests can tag another call's duration (metrics-only distortion); an incomplete HF snapshot (missing config) surfaces as 500 instead of `E_NO_MODEL`; `test_golden_parity.py:57-64` skips on size mismatch instead of failing (a corrupt mount silently skips the gate — check_golden.py still fails hard, so the gate exists); image path returns cached lists by reference vs text path copying.
