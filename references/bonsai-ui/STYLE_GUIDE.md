# Bonsai Serve / ZenMeter UI style guide (Material 3 Expressive, as built by hand)

Source apps (read-only originals): `/home/martin/projects/phone-llm-serve` (Bonsai Serve) and `/home/martin/projects/zenmeter`.
Verbatim copies are in `src/bonsai-serve/` and `src/zenmeter/` next to this file. No keystores, keys or native libs were copied.
Rule from Martin: every app is M3 Expressive unless told otherwise.

## 0. Key finding: it is "Expressive by hand", not the Expressive theme API

Neither app calls `MaterialExpressiveTheme`, `MotionScheme`, `MaterialShapes`, `LoadingIndicator`, `ButtonGroup`, split/toggle buttons, or `@OptIn(ExperimentalMaterial3ExpressiveApi)`. They use plain `MaterialTheme` from material3 1.4.0 and re-create the Expressive look manually:

- Expressive spring motion: constants copied from material3's `ExpressiveMotionTokens` (read from 1.4.0 bytecode, 2026-10-27).
- Expressive shape language: very large and asymmetric corner radii, a corner that morphs on state change.
- Expressive type: Black-weight (900) display/headline text, all-caps tracked labels, huge numerals.
- Dynamic colour (Material You), tonal container cards, haptics on every action.

The comment in the source says the Expressive theme/motion APIs were `internal` in 1.4.0 and became public in 1.5 (which then needed compileSdk 37 + AGP 9, "not on this toolchain"). See section 8 for what is true today.

## 2. Theme

```kotlin
@Composable
private fun Theme(content: @Composable () -> Unit) {
    val ctx = LocalContext.current; val dark = isSystemInDarkTheme()
    val cs = if (Build.VERSION.SDK_INT >= 31) { if (dark) dynamicDarkColorScheme(ctx) else dynamicLightColorScheme(ctx) }
    else if (dark) darkColorScheme(primary = Color(0xFF5EEAD4)) else lightColorScheme(primary = Color(0xFF006B5F))
    MaterialTheme(colorScheme = cs, content = content)
}
```

- Dynamic colour on Android 12+ (wallpaper-derived), automatic light/dark from the system. Fallback seed (API < 31, never hit at minSdk 30 in practice for 30 only): teal `#006B5F` light, `#5EEAD4` dark primary; ZenMeter also sets tertiary amber `#8A5100` / `#FFB86B`.
- No custom `Typography`, no custom `Shapes`, no custom fonts: everything comes from `MaterialTheme.typography` and is overridden per call site with `.copy(fontWeight = Black)`.
- No dark-mode toggle in-app; follows the system. Colours are only ever read from `MaterialTheme.colorScheme` roles (never hard-coded in the UI), so dark mode and dynamic colour just work.
- Root background is `cs.surface`, set on the root Column (no Scaffold).

## 3. Design tokens

Motion (the heart of the "expressive" feel; copy exactly):

```kotlin
private object Motion {
    fun <T> spatial()     = spring<T>(0.8f, 380f)   // default spatial: position/size/shape, overshoots
    fun <T> fastSpatial() = spring<T>(0.6f, 800f)   // press feedback
    fun <T> slowSpatial() = spring<T>(0.8f, 200f)
    fun <T> effects()     = spring<T>(1f, 1600f)    // default effects: colour/alpha/numbers, no overshoot
    fun <T> fastEffects() = spring<T>(1f, 3800f)
    fun <T> slowEffects() = spring<T>(1f, 800f)
}
```
Rule: spatial springs for anything that moves or changes shape; effects springs (damping 1) for colour, alpha, numbers.

Shapes (all `RoundedCornerShape`, dp):
- Hero card: `44.dp` uniform.
- Asymmetric "leaf": `RoundedCornerShape(topStart=16, topEnd=52, bottomEnd=16, bottomStart=52)` (and its mirror `16,52,16,52`).
- Stat tiles in a 2-column row, diagonal pair: left `36,12,36,12`, right `12,36,12,36`; alternate which side gets which across rows (checkerboard).
- Big toggle surface: corner animates `64.dp` (on, near pill) <-> `28.dp` (off).
- Progress bars: height 14.dp, rounded caps, clipped to `RoundedCornerShape(7.dp)`.

Typography (stock M3 scale, `Black` = FontWeight.Black on everything prominent):
- Screen title: `displayMedium` Black, subtitle `titleMedium` in `onSurfaceVariant`.
- Section label inside card: `labelLarge` Black, `letterSpacing = 1.5.sp`, ALL CAPS literal text ("STATUS", "ACTIVITY", "API KEY (tap to copy)").
- Big state: `displaySmall` Black UPPERCASE; hero numerals `displayLarge` with `fontSize = 72.sp` / `56.sp`, Black.
- Tile label: `labelSmall` Black, letterSpacing 1.sp, uppercase; tile value `headlineMedium` Black.
- Body: `bodyLarge` / `bodyMedium`; machine values (URLs, keys, logs) in `FontFamily.Monospace`.

Spacing: screen padding 16.dp horizontal / 12.dp vertical; 12.dp between cards (`Arrangement.spacedBy(12.dp)`); card inner padding 28.dp (hero), 24.dp (small leaf), `18.dp, 16.dp` (tiles); header indented `start = 8.dp`; trailing `Spacer(24.dp)`.

Colour usage (tonal containers carry meaning):
- Primary state/hero: `primaryContainer` on `onPrimaryContainer`; secondary stats `secondaryContainer`; activity/progress `tertiaryContainer`; neutral idle/info `surfaceContainerHigh` on `onSurface`; warning/hot `errorContainer` on `onErrorContainer`; off/killed `errorContainer` (Bonsai) or `surfaceContainerHighest` (ZenMeter).
- State changes recolour the SAME card (e.g. status card: ready=primaryContainer, starting=tertiaryContainer, off=surfaceContainerHigh).
- Progress: `color = cs.tertiary` (cs.error above 85%), `trackColor = onContainer.copy(alpha=0.15f)`.

## 4. Component inventory (what is actually used)

All from `androidx.compose.material3.*` 1.4.0: `MaterialTheme`, `Card` (plain and `onClick` variant), `CardDefaults.cardColors(container, content)`, `Surface(onClick=...)` (as the big switch container), `Switch` (display-only, `onCheckedChange = null`, `thumbContent` with a check/cross glyph, scaled 1.5x via graphicsLayer), `Button`, `TextButton`, `FilterChip` (model picker, one per .gguf), `LinearProgressIndicator` (determinate with `progress = { }`, indeterminate when waiting; `gapSize = 0.dp`, `drawStopIndicator = {}` to drop the 1.4 stop dot and gap), `Text`, `Spacer`.
NOT used: Scaffold, TopAppBar, NavigationBar/Rail, FAB, Dialogs, Snackbar, TextField, LazyColumn, Icon/IconButton, ButtonGroup, SplitButton, ToggleButton, LoadingIndicator, FloatingToolbar, carousel.

Custom pieces to copy (all in MainActivity.kt):
- `Modifier.springIn(i)`: staggered entrance. `Animatable(0f)`; after `delay(i*80ms)` animate to 1 with the spatial spring; graphicsLayer scale 0.8->1.0, alpha 0->1, translationY 90px->0. Give each card an increasing index (0,1,2...).
- `Num(value, decimals, style, color)` (ZenMeter): number that counts to its new value (`animateFloatAsState` with slowEffects) and gives a bouncy 1.08x scale bump (`Animatable.snapTo(1.08f)` then `spring(0.35f, 380f)`) when it changes (first composition is skipped).
- `Tile(label, value, bg, fg, shape, modifier)` (ZenMeter): stat card = uppercase tiny label + animated number.
- Press feedback on big tappable surfaces: `MutableInteractionSource` + `collectIsPressedAsState`; scale 1 -> 0.94 with `fastSpatial`; plus corner morph (`animateDpAsState`), colour crossfade (`animateColorAsState` with effects spring) on state change.
- Haptics (`LocalHapticFeedback`): `Confirm` (copy, became ready, finished), `ToggleOn` / `ToggleOff` (switch), `Reject` (error event), `LongPress` (busy started). Fired both on tap and on self-triggered state changes (`LaunchedEffect(state)`).

## 5. Layout per screen (single screen apps)

One `Dashboard()` composable, no navigation, no Scaffold:

```
Column(fillMaxSize, background(cs.surface), windowInsetsPadding(WindowInsets.safeDrawing),
       verticalScroll, padding(16.dp,12.dp), spacedBy(12.dp))
```
Bonsai Serve, top to bottom (each wrapped in `springIn(index)`):
1. Header: "Bonsai server" displayMedium Black + subtitle.
2. STATUS hero card (44.dp corners, colour by state): caps label, big UPPERCASE state word, monospace endpoint URL, model/context line, uptime line, optional error line; when waiting: filled `Button` "Connect / authorize VPN" + indeterminate `LinearProgressIndicator`.
3. ACTIVITY leaf card (16/52/16/52): label, state word, 14.dp determinate progress bar while prompt processing, speed text, row of three stat columns (IN / OUT / REQUESTS with big Black numbers), disk-cache line, `TextButton` "Reset totals".
4. Row of two tiles (RAM FREE secondary, BATTERY surfaceContainerHigh -> errorContainer when > 42 degrees), diagonal corner pair.
5. API KEY card (clickable, copies to clipboard + Confirm haptic), monospace masked key, `TextButton`.
6. MODEL section: caps label + a `FilterChip` per model (single select).
7. Kill-switch `Surface(onClick)`: full-width, big headline "Server" + state sentence + 1.5x scaled `Switch`. Corner/colour/scale animated.
8. Monospace small-text log tail + events in `onSurfaceVariant`.
ZenMeter: same skeleton: header, TRAFFIC hero (72.sp animated number + MB units + up/down rows), FRESH TOKENS leaf card with requests progress bar, three rows of two `Tile`s (checkerboard shapes), the one control Surface/Switch, small status text lines.

State plumbing: UI polls a snapshot every 500 ms to 1 s (`LaunchedEffect { while(true){ delay(...) } }` or `produceState`) and re-renders; ViewModel/Flow not used. Fine for scanlist to use a ViewModel + StateFlow instead; styling is independent of it.

## 6. Edge-to-edge, icons, dark mode

- `enableEdgeToEdge()` in `onCreate` (before `setContent`), and the root Column uses `windowInsetsPadding(WindowInsets.safeDrawing)` so content clears status bar, nav bar, cutout and keyboard. Manifest theme `Theme.Material.NoActionBar`.
- Icons: none in the UI. App icon = adaptive icon (vector fg, solid `#10261C` bg, monochrome layer). Notification icon = monochrome vector. In-UI glyphs are Unicode (check, cross, arrows).
- Dark mode: system-driven via `isSystemInDarkTheme()`, dynamic colour for both.
- Not screenshotted: `adb devices` showed no connected device, so the look above is reconstructed from the code.

## 8. Current state of the real Expressive APIs (web check, 2026-11-16)

Verified from the official release page, [Compose Material 3 releases](https://developer.android.com/jetpack/androidx/releases/compose-material3) (page text as fetched):
- Stable `1.4.0`; RC `1.5.0-rc01` (2026-11-04); beta `1.5.0-beta02` (2026-10-21); last alpha `1.5.0-alpha29`.
- Promotions during the 1.5.0 alphas: motion scheme graduated from experimental (alpha15); `MaterialExpressiveTheme` / `expressiveLightColorScheme` promoted (alpha18, plus an `@Material3ExpressiveApi` annotation not needing OptIn); `ToggleButton` stable (alpha19); `SplitButton` non-experimental (alpha20, `SplitButtonLayout` deprecated for `SplitButton` in alpha25); `ButtonGroup` stable and expressive `FloatingToolbar` graduated (alpha22); `TopAppBar`, `FlexibleBottomAppBar` graduated (alpha23). `MaterialShapes`/`LoadingIndicator` promotion was reverted in alpha19; a third-party summary says they still need the opt-in on later alphas (unverified, not an official source).
- Renames/breaks since 1.4.0 worth knowing: `Slider`/`RangeSlider` `onValueChange` now required and reordered (alpha29); `PolygonShape` API reworked (beta01: `CornerRounding` top-level, `transform{}`/`copy()` replace `transformed()`/`scaledToFit()`); `HorizontalCenteredHeroCarousel` `maxItemWidth` -> `preferredItemWidth`; `SplitButtonLayout` -> `SplitButton`; `WideNavigationRail` experimental overloads removed (alpha20).
- compileSdk: sources conflict. The release page says alpha23 "Remove requirement for compileSdk 37", but it also notes Compose libraries moved to compileSdk 37.1 later (material3-a2ui alpha01, 2026-09-23), and [Android Developers Blog, Compose August 2026](https://android-developers.googleblog.com/2026/08/jetpack-compose-august-2026-release.html) says Compose 1.12 / BOM 2026.08.00 requires compileSdk 37 and AGP 9.1.1+. Not verified on this machine: only an actual `./build.sh` with 1.5.0-rc01 on SDK 35 will tell. Also [December 2025 post](https://android-developers.googleblog.com/2025/12/whats-new-in-jetpack-compose-december.html) says Expressive APIs lived in the alphas while 1.4 was stable.
- Search could not confirm the exact opt-in status of `MaterialExpressiveTheme` in 1.5.0-rc01; check the source/IDE.

Recommendation for scanlist: start with the proven recipe (material3 1.4.0, SDK 35, hand-made expressive as above) so it builds on this toolchain today. As a second step, try `androidx.compose.material3:material3:1.5.0-rc01` (needs newer SDK platform 36/37 and possibly AGP 9 in the toolchain; check `android-toolchain/sdk`), then switch `MaterialTheme` to `MaterialExpressiveTheme(motionScheme = MotionScheme.expressive(), ...)`, replace the hand `Motion` object by `MaterialTheme.motionScheme.defaultSpatialSpec()` etc, and adopt `ButtonGroup`, `ToggleButton`, `SplitButton`, `FloatingToolbar`, `LoadingIndicator`. Keep the card shapes/typography rules from section 3 either way (the Expressive theme gives the motion and a `MaterialShapes` set, but the Black-weight type and asymmetric cards are this project's own look).
